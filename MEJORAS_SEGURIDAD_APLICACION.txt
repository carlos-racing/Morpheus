MEJORAS RECOMENDADAS PARA MORPHEUS
==================================

Este documento recoge mejoras pendientes tanto de seguridad como de mantenimiento
de la aplicacion. No son cambios aplicados, sino una lista de trabajo priorizada.


1. SEGURIDAD CRITICA
--------------------

1.1. Cambiar contrasenas expuestas
- Cambiar la contrasena del usuario Mongo e2t.
- Cambiar la contrasena root/admin de Mongo si ha sido compartida.
- Cambiar la contrasena inicial del usuario admin de la aplicacion.

1.4. Anadir CSRF
- Proteger todos los formularios POST contra CSRF.
- Afecta a login, asignacion, desocupacion, gestion de usuarios, gestion de edificio y eliminaciones.

1.5. Seguridad de sesiones
- Configurar SESSION_COOKIE_HTTPONLY.
- Configurar SESSION_COOKIE_SAMESITE.
- Configurar SESSION_COOKIE_SECURE cuando se use HTTPS.
- Revisar duracion de sesion y cierre automatico.


2. SEGURIDAD EN SUBIDA DE ARCHIVOS
----------------------------------

2.1. Validar nombres de archivo
- No guardar directamente file.filename.
- Usar nombres generados internamente o secure_filename.

2.2. Limitar tamano de subida
- Definir MAX_CONTENT_LENGTH en Flask.
- Evitar subidas enormes que puedan tumbar la aplicacion.

2.3. Validar contenido real
- Comprobar extension y tambien estructura esperada.
- Validar columnas obligatorias.
- Rechazar filas vacias o datos inconsistentes.

2.4. Gestionar archivos temporales
- Borrar Excels subidos despues de procesarlos si no hacen falta.
- Mantener app/uploads fuera de Git.


3. MEJORAS DE BASE DE DATOS
---------------------------

3.1. Indices Mongo recomendados
- bed_id con indice unico.
- estado.
- planta, zona, modulo, habitacion.
- brigada.
- numero_alumno.

3.2. Normalizar estados
- Guardar siempre OCUPADA o DESOCUPADA.
- Aceptar variantes como Ocupada, ocupada, Desocupada, etc. solo al importar o recibir datos.

3.3. Backups
- Crear backup automatico de MongoDB.
- Guardar copia periodica de la base Morpheus.
- Probar restauracion, no solo generacion del backup.

3.4. Usuarios
- Evitar usuarios admin compartidos.
- Crear usuarios personales si varias personas acceden.
- Revisar roles y permisos.


4. MEJORAS DE APLICACION
------------------------

4.1. Dividir app/routes.py
- Separar autenticacion.
- Separar gestion de camas.
- Separar importacion Excel.
- Separar gestion de usuarios.
- Separar gestion de edificio.
- Separar vistas de impresion.

4.2. Crear capa de servicios
- Centralizar operaciones sobre camas.
- Centralizar operaciones sobre usuarios.
- Evitar consultas Mongo repetidas directamente en cada ruta.

4.3. Mejorar validacion de Excel
- Validar columnas obligatorias.
- Validar duplicados de bed_id.
- Validar duplicados de numero_alumno.
- Validar estado, genero, brigada y especialidad.
- Informar errores por fila.

4.4. Evitar cargar toda la BD cuando no sea necesario
- Algunas consultas cargan todas las camas y filtran en Python.
- Usar filtros Mongo directos cuando sea posible.

4.5. Mejorar mensajes de error
- Mostrar errores claros cuando falla una importacion.
- Diferenciar error de formato, columnas, permisos o base de datos.

4.6. Anadir endpoint de salud
- Crear /health para comprobar si la app responde.
- Util para Docker, Nginx y monitorizacion.

4.7. Logs propios de aplicacion
- Registrar errores de importacion.
- Registrar acciones criticas: asignar, desocupar, eliminar brigada, crear usuario.
- No depender solo de logs de Nginx.

6. TESTS Y CALIDAD
------------------

6.1. Tests minimos
- Login correcto e incorrecto.
- Consulta de camas.
- Asignacion de cama.
- Desocupacion de cama.
- Eliminacion de brigada.
- Importacion de camas.
- Creacion de usuario.

6.2. Validacion antes de desplegar
- python -m py_compile.
- docker compose config.
- docker compose up -d --build.
- Prueba manual de login, consulta, asignacion e importacion.

6.3. Limpieza de dependencias
- Revisar requirements.txt.
- Eliminar dependencias de desarrollo que no se usen en produccion si procede.
