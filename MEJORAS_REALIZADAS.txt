MEJORAS REALIZADAS EN MORPHEUS
==============================

Este documento recoge mejoras ya aplicadas al proyecto.


1. SEGURIDAD
------------

1.1. Sacar secretos del codigo versionado actual
Fecha: 2026-05-14

Cambios realizados:
- Eliminadas credenciales reales hardcodeadas de app/config.py.
- Eliminada la SECRET_KEY por defecto del codigo.
- MONGO_URI y SECRET_KEY pasan a ser variables de entorno obligatorias.
- Eliminadas credenciales reales de docker-compose.yml.
- docker-compose.yml exige SECRET_KEY, MONGO_URI y ADMIN_PASSWORD mediante variables de entorno.
- Eliminadas credenciales reales de .env.example.
- .env.example conserva solo placeholders sin secretos reales.
- Eliminadas credenciales reales de import_beds.py.
- Eliminadas credenciales reales de crear_usuario.py.
- crear_usuario.py exige ADMIN_PASSWORD mediante variable de entorno.
- DEPLOY.md ya no documenta credenciales reales.

Revision realizada:
- Busqueda en archivos versionados para detectar MONGO_URI, SECRET_KEY y contrasenas hardcodeadas.
- Revision del historial de Git con git grep sobre todos los commits.
- El historial contiene secretos en commits anteriores, incluyendo credenciales Mongo y SECRET_KEY antiguas.

Nota importante:
- Aunque ya no hay secretos reales en los archivos actuales, el historial de Git y GitHub puede conservar credenciales anteriores.
- Para completar la limpieza historica de forma real hay que reescribir historial con una herramienta como git-filter-repo o BFG, forzar subida a GitHub y despues rotar todas las credenciales expuestas.

1.2. Purgar secretos del historial de Git
Fecha: 2026-05-14

Cambios realizados:
- Reescrito el historial local de Git con git filter-branch.
- Sustituidas credenciales Mongo antiguas por placeholders en commits historicos.
- Sustituida SECRET_KEY antigua por placeholder en commits historicos.
- Eliminadas referencias historicas a valores por defecto inseguros de ADMIN_PASSWORD y SECRET_KEY.
- Eliminados de la historia los directorios env/, __pycache__, app/__pycache__ y app/uploads.
- Eliminadas refs/original y reflogs locales.
- Ejecutado git gc --prune=now --aggressive para compactar objetos locales.
- Alineadas las referencias locales origin/main y origin/HEAD con la historia purgada.

Verificacion realizada:
- Busqueda en todos los commits locales con git grep sobre git rev-list --all.
- No se encontraron coincidencias para las credenciales conocidas ni para las cadenas sensibles buscadas.

Aviso importante:
- La historia remota debe subirse con force push.
- Cualquier clon existente debe volver a clonar el repositorio o resincronizarse contra la nueva historia.
- Aunque se purgue Git, las credenciales expuestas deben considerarse comprometidas y rotarse.

1.3. Limitar exposicion de MongoDB a la red interna
Fecha: 2026-05-15

Cambios realizados:
- Activado UFW en el servidor.
- Permitido acceso a MongoDB por el puerto 27017 desde la red interna 192.168.0.0/16.
- Permitido acceso a MongoDB desde la red Docker de Morpheus 172.28.0.0/16.
- Denegado acceso general al puerto 27017 desde cualquier otro origen.
- Mantenido MongoDB accesible para la LAN, otros contenedores y usos de docencia.
- Aniadida regla UDP para TeamSpeak en el puerto 9987.
- Identificado el puerto 9090 como acceso web de administracion del servidor y mantenido abierto.
- Creado/configurado un usuario especifico de MongoDB para Morpheus con permisos sobre la base Morpheus.
- Actualizado Morpheus para usar el usuario especifico de la aplicacion en lugar de root/admin.

Estado UFW esperado para MongoDB:
- ALLOW 192.168.0.0/16 -> 27017/tcp.
- ALLOW 172.28.0.0/16 -> 27017/tcp.
- DENY resto -> 27017/tcp.

Nota:
- MongoDB sigue publicado para la red interna porque se usa en clases y por otros servicios.
- No se debe usar el usuario root/admin de MongoDB desde aplicaciones.

- Configurado el dominio interno morpheus.eeae.es para acceder a la aplicacion.

1.8. Seguridad de sesiones
Fecha: 2026-05-19

Cambios realizados:
- Configurado SESSION_COOKIE_HTTPONLY para impedir acceso a la cookie desde JavaScript.
- Configurado SESSION_COOKIE_SAMESITE=Lax para reducir envio de cookies en navegaciones externas.
- Aniadida configuracion SESSION_COOKIE_SECURE mediante variable de entorno.
- Aniadida duracion configurable de sesion con SESSION_LIFETIME_MINUTES.
- Cambiado el login para limpiar la sesion anterior y crear una sesion permanente con caducidad.
- Conservado el cierre automatico de sesion al cerrar pestana o ventana mediante /logout_auto.
- Documentado en DEPLOY.md que produccion detras de HTTPS debe usar SESSION_COOKIE_SECURE=true.

Notas:
- En local puede mantenerse SESSION_COOKIE_SECURE=false para poder usar http://127.0.0.1:5000.
- En produccion con https://morpheus.eeae.es debe configurarse SESSION_COOKIE_SECURE=true en el .env del servidor.
